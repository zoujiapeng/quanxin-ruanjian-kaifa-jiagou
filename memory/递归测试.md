**核心思路:** 递归测试 = 用 Lobster 自己测试自己。

Claude Code（入口）→ 用 Lobster 能力（终端/模拟输入）打开新终端跑 `claude` → 模拟发送自然语言 prompt → 新 Claude 实例执行 Lobster 项目任务。

**关键要求:** 发送的 prompt 必须是"其他同类项目做不到的任务"（如 GUI 操作、OCR、颜色检测、进度条监控等），这正是 Lobster 的价值验证。

**Why:** 普通自动化项目只能做 CLI/API 调用，Lobster 能操作 GUI、感知屏幕、循环监控。递归测试验证的是这个核心差异——如果 Lobster 能驱动 Claude Code 完成这类任务，就证明了它做到了其他项目做不到的事。

**How to apply:** 设计测试场景时，优先选择需要"感知→决策→动作→验证"闭环的任务。通过 Lobster 的 DSL 编排（LOOP/WAIT/IF + OCR/CLICK/COLOR_CHECK），让新 Claude 实例在实际 GUI 环境中工作。
